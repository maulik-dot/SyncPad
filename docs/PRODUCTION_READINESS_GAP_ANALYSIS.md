# Production Readiness & Architecture Gap Analysis

This document provides a transparent, comprehensive audit of features that are simulated, prototype-level, or missing compared to a full enterprise production posture.

---

## 1. Security & Authentication Posture

### SCIM v2 User Provisioning (`/scim/v2/**`)
- **Previous Exposure**: `/scim/v2/**` was previously declared in `.permitAll()` inside `SecurityConfig.java`, allowing unauthenticated actors to query, create, update, and delete users via REST.
- **Remediation Implemented**:
  - Registered `ScimAuthenticationFilter` in Spring Security filter chain before `UsernamePasswordAuthenticationFilter`.
  - Only public metadata discovery endpoints (`/scim/v2/ServiceProviderConfig` and `/scim/v2/Schemas`) remain accessible without credentials per RFC 7644.
  - All user provisioning endpoints (`/scim/v2/Users/**`) strictly require a valid Bearer token (`SCIM_BEARER_TOKEN`) or authenticated Administrator credentials. Unauthenticated requests receive HTTP 401 with standard SCIM error JSON schema (`urn:ietf:params:scim:api:messages:2.0:Error`).

### Enterprise Single Sign-On (`/auth/sso/**`)
- **Status**: **Simulation Mode / Prototype**
- **Details**:
  - `SsoProvisioningService.java` generates dual JWT tokens based on user email and domain matching.
  - It does **not** perform full cryptographic SAML 2.0 assertion validation (XML signature verification, IdP certificate trust store, XML encryption, replay detection) or full OIDC Authorization Code Flow with PKCE.
- **Remediation Implemented**:
  - SSO is now explicitly **disabled by default** via `app.sso.enabled=false` (`SSO_ENABLED=false` in `.env.example`).
  - Production deployments reject unverified SSO attempts unless a cryptographic ID token/assertion is provided.
  - Development environments must explicitly declare `SSO_SIMULATION_MODE=true` to enable mock testing, which emits prominent `WARN` audit logs.
- **Production Recommendation**:
  - Integrate `spring-security-saml2-service-provider` for corporate SAML 2.0 integrations (Okta, Azure AD).
  - Use Google OAuth2 Client ID (`GOOGLE_CLIENT_ID`) for real Google Sign-In verification, already natively supported in `AuthService.java`.

## 2. Secrets Management & Cloud Providers

### Vault, AWS Secrets Manager & GCP Secret Manager
- **Context Initializer Registration**:
  - `SecretApplicationContextInitializer` is now registered in `application.properties` via `context.initializer.classes`.
  - If Vault (`VAULT_ADDR` + `VAULT_TOKEN`), AWS, or GCP environment settings are provided, it executes at highest precedence before any Spring beans are initialized.
- **AWS & GCP Provider Architecture**:
  - `AwsSecretsManagerProvider` and `GcpSecretManagerProvider` parse JSON environment payloads (`AWS_SECRET_PAYLOAD` and `GCP_SECRET_PAYLOAD`) typically mounted into container runtime environments by AWS ECS Secrets integration, Kubernetes External Secrets Operator, or GCP Cloud Run secret mounts.
  - They do **not** invoke AWS SDK (`software.amazon.awssdk`) or GCP SDK (`com.google.cloud`) network APIs directly in Java code. This keeps container footprint light and memory overhead low while delegating secret retrieval and rotation to cloud orchestrators.

## 3. Generative AI vs. Local Template Synthesis

### Gemini Integration & Transparent Fallbacks
- **Generative AI**: Enabled when `GEMINI_API_KEY` is provided with a valid Google Gemini API key. Calls `gemini-flash-lite-latest` or configured models with automated alias fallback.
- **Offline / Quota Fallback**:
  - When no API key is supplied or when upstream Gemini quotas are exhausted, `AiAssistantService.java` synthesizes structured markdown templates locally (e.g. summarizing text, drafting meeting notes, boilerplate Python code).
- **Transparency Hardening**:
  - The API response now explicitly indicates whether the response came from generative AI or local synthesis:
    - HTTP Header: `X-AI-Fallback: true` (or `false`)
    - JSON DTO: `"fallback": true`, `"modelUsed": "SyncPad Local Template Synthesis (Offline Fallback)"`
  - Clients and users are never misled into believing offline templates were generated by live LLM inference.

## 4. Frontend Assets & Prototypes

### Static Vanilla UI vs. React Design Workspace
- **Production Asset Delivery**:
  - The primary application served by Spring Boot (`src/main/resources/static/`) and Nginx on port 80 is the responsive vanilla JavaScript frontend.
  - Duplicate unclosed `<script src="...sockjs.min.js">` tags in `index.html` have been removed.
  - Offline sync is handled by `js/offline/offline-sync.js` (`syncpad_local_store`), with `js/offline/syncpad-offline.js` retained for test suite and backward compatibility.
- **React Design Prototype (`Document Workspace Design/`)**:
  - The React + Vite project in `Document Workspace Design/` was developed as an advanced design prototype and component testbed.
  - CI compiles it with `pnpm build` to verify type safety and build health, but Docker deployment deliberately serves `src/main/resources/static/` to avoid multi-gigabyte build artifacts and preserve zero-node container runtimes.

## 5. Observability, Metrics & Production Posture

### Current Observability Implementation:
- **Micrometer & Actuator**: Exposes `/actuator/prometheus`, `/actuator/health/liveness`, `/actuator/health/readiness`, and `/actuator/info`.
- **HikariCP & JVM Metrics**: Monitored via Prometheus (`monitoring/prometheus.yml`) and visualized via Grafana (`monitoring/grafana/`).
- **Grafana Credentials**:
  - Hardened `monitoring/docker-compose.monitoring.yml` to require `GRAFANA_ADMIN_PASSWORD` from the environment; hardcoded fallback password (`admin_syncpad_2026`) has been removed.
- **Alertmanager**:
  - `monitoring/alertmanager.yml` configured with routing rules and documented integration hooks for PagerDuty, Slack, and webhook receivers.

### Enterprise Observability Roadmap (Gaps for Full Fleet Production):
1. **OpenTelemetry / Distributed Tracing**:
   - Add OpenTelemetry Java Agent (`-javaagent:opentelemetry-javaagent.jar`) or Spring Cloud Sleuth / Micrometer Tracing with W3C `traceparent` propagation to trace requests across Nginx, Spring Boot, PostgreSQL, and RabbitMQ.
   - Include `trace_id` and `span_id` in logback MDC patterns.
2. **Centralized Logging**:
   - Ship container logs to Loki or Elasticsearch via Promtail or FluentBit.
3. **Database & Broker Exporters**:
   - Deploy `postgres-exporter` to capture database replication lag, lock contention, and index hit ratios.
   - Deploy `rabbitmq-server` Prometheus plugin (`rabbitmq_prometheus`) to monitor queue depths, unacknowledged messages, and STOMP connection counts.
4. **Kubernetes Operators**:
   - For Kubernetes deployments, deploy the Prometheus Operator with custom `ServiceMonitor` resources targeting the `app` pod ports on `/actuator/prometheus`.
