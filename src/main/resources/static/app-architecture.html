System Overview

SyncPad is a collaborative workspace app with a Spring backend and a rich browser client.

Users authenticate with JWT, browse workspaces and folders, edit documents and whiteboards, attach PDFs, collaborate in realtime over WebSockets, and persist data in PostgreSQL through JPA repositories and service-layer permission checks.

Browser UI -> REST API (/auth, /documents, /workspaces, /folders, /notifications) -> Spring Controllers -> Service Layer -> JPA Repositories -> PostgreSQL Browser UI -> STOMP over /ws -> /app/documents/* + /topic/* -> Realtime document, notification, and PDF annotation updates

Main Runtime Flow

1. AuthenticateLogin, register, or Google sign-in returns a JWT.
2. Load Workspace DataThe UI fetches workspaces, folders, documents, comments, versions, and notifications.
3. Edit and CollaborateREST saves durable data; WebSockets broadcast live presence and document updates.
4. Persist and RestoreDocument versions, permissions, notifications, and attachments are reloaded on future sessions.

Backend Structure

`controller/`Exposes REST endpoints and STOMP message mappings.
`service/`Contains business logic: permissions, sharing, versions, notifications, comments, folders, workspaces.
`repository/`Spring Data JPA repositories used by services to query and persist entities.
`entity/`JPA domain model for users, workspaces, folders, documents, permissions, comments, versions, notifications, and share links.
`security/`JWT parsing, auth filter, user details service, and route security configuration.
`config/`OpenAPI docs, WebSocket broker configuration, and demo seed data.

Frontend Structure

`index.html`The main app shell. It contains the auth UI, workspace UI, editor, whiteboard, notifications, PDF pane, and large embedded application script.
`app.css`Shared design system: light/dark theme tokens, layout primitives, cards, buttons, editor visuals, and PDF styles.
`js/doc/latex-compiler.js`LaTeX/Katex rendering for rich document content.
`js/pdf/*`Modular PDF engine for rendering, annotation, capture, persistence, selection, history, and collaboration.

Core Data Model

UserIdentity, email/password or Google provider metadata.
Workspace + WorkspacePermissionTop-level collaboration space plus per-user role mapping.
FolderOrganizes files inside a workspace-style grouping.
Document + DocumentPermissionEditable content item with per-user access role.
DocumentVersionSnapshot history for restore and audit-like views.
DocumentCommentThreaded comments with replies and resolved state.
ShareLinkTokenized document access with role and expiry.
NotificationWorkspace invites, accept/decline flow, and role update events.

Security Model

Stateless JWTUsers receive a signed token after auth. The browser stores it and includes it on protected requests.
Spring Security Filter`JwtAuthenticationFilter` validates bearer tokens and sets the authenticated principal.
Permission EnforcementServices check `DocumentPermission` and `WorkspacePermission` before allowing reads, edits, sharing, restore actions, and membership updates.
WebSocket AuthThe STOMP `CONNECT` frame can carry the JWT, which is validated in `WebSocketConfig`.

How a Typical Session Works

AuthenticationThe user signs in on the static client. `/auth/login`, `/auth/register`, or `/auth/google` returns a token and user identity.
Workspace BootThe client fetches `/workspaces`, then workspace-scoped folders and accessible documents. Local UI state is restored from `localStorage` where relevant.
Document OpenOpening a document loads detail, comments, stats, versions, and any attached PDF metadata. The editor view becomes the active surface.
Live CollaborationThe client connects to `/ws`, subscribes to `/topic/documents/{id}`, and broadcasts edit/cursor messages to `/app/documents/{id}/edit`.
PersistenceExplicit document saves go through the service layer, update the `Document`, and create a new `DocumentVersion` snapshot.
NotificationsWorkspace invites and membership changes persist in `Notification` records and are pushed live over `/topic/notifications/{email}`.

Document Engine

CRUD + RenameDocuments can be created, updated, renamed, deleted, and filtered by folder or type.
PermissionsOwners can share; viewers cannot edit; collaborators receive role-based access.
VersionsEvery create/update/restore action can create a `DocumentVersion` snapshot for history.
CommentsUsers can create comment threads, reply, resolve, and delete based on ownership/role.
Share LinksShare tokens can grant role-based document access with expiry and revocation.

PDF Engine

RendererUses PDF.js for real PDF files and a vector fallback library for built-in reference documents.
Annotation ToolsPointer, text select, pen, highlighter, underline, rectangle, arrow, text box, sticky note, eraser.
CaptureUsers can select a region, extract text, generate a snapshot, or insert captured content into the main document.
PersistenceUploaded PDFs are stored client-side in IndexedDB; annotations are stored in `localStorage` and separated by user, doc, and PDF key.
Realtime SyncPDF annotations are synced over STOMP to `/topic/documents/{id}/pdf-annotations`.

Primary API Surface

`/auth/*`Register, login, Google login, and auth config.
`/documents/*`CRUD, details, stats, versions, restore, comments, sharing, share links, PDF metadata.
`/workspaces/*`Workspace CRUD, invites, sharing, member list, member role updates, recent files.
`/folders/*`Folder CRUD and subfolder access.
`/notifications/*`Inbox, unread count, accept/decline invite, mark read, delete, clear all.

Realtime Channels

`/ws`STOMP/SockJS endpoint used by the browser.
`/app/documents/{id}/edit`Broadcasts document edits, cursor positions, and presence messages.
`/app/documents/{id}/save`Triggers durable document update through the backend.
`/topic/documents/{id}`Subscribers receive document collaboration events.
`/app/documents/{id}/pdf-annotation`Pushes PDF annotation mutations.
`/topic/notifications/{email}`Pushes invite and role-change notifications to a user.

Deployment and Runtime Environment

Maven BuildThe project uses `pom.xml` with Spring Boot, JPA, Security, WebSocket, Validation, PostgreSQL, and OpenAPI dependencies.
DockerThe `Dockerfile` builds the jar in a Maven image and runs it in a Temurin JRE image.
Compose`docker-compose.yml` starts PostgreSQL and the app on port `8082`.
SwaggerInteractive API docs are exposed through Springdoc at `/swagger-ui/index.html`.
